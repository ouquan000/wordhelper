# 1.4.7.1 设计与决策记录（2026-11-10）

1.4.7.1 是在 1.4.7「远程同步专版」之上的一版质量修复：让「用户说哪里不好」真正影响生成与验收，并把远程同步的可靠性补到可长期使用的程度。云端能力不变，App 仍是「一次粘整行」的用法。

## 1. 版本号

- `versionName = "1.4.7.1"`，`versionCode = 14`（`app/src_repo/app/build.gradle.kts:16-17`）。
- 1.4.7 按用户要求没 bump（显示 1.4.6.2 / vc13），1.4.7.1 补上，便于真机与电脑端对账。
- **回滚注意**：本版 DB 从 20 升到 21，旧 APK 打不开新库（Room 降级失败）。回退 1.4.7 只能卸载重装，不能覆盖安装回退（**本机进度会丢**）。

## 2. 反馈闭环（F1）

### 2.1 问题不是生成，是验收

实验鱼用 3 个真实 👎 词（chronic / hemisphere / cathedral）在隔离副本上跑了 36 次生成：

- 现状的三个词在「盲评」下全部首轮通过（8/8/9 分），cathedral 交付的仍是用户刚否掉的思路。**用户必第二次 👎，而系统认为自己交了 8 分卡。**
- 让评委看见抱怨后，能抓到盲评抓不到的错（cathedral 的「同一条思路换措辞」被判 3 分并逼出真换招），但原 `min>=8` 门会把正确的改稿判死（谐音 7 分），两轮白卷。
- 只收紧关卡 = 更少的卡，不是更好的卡。

### 2.2 两段式通过条件

有用户意见（instruction 非空）时：

1. 六维全 ≥ 8 **且** 诉求落实 ≥ 8；或
2. 诉求落实 ≥ 8 且六维 ≥ 6 且无 0 分。

没有用户意见时保持原规则（六维全 ≥ 8）。评委新增第 7 维「诉求落实」，并在 prompt 里看到用户原话与上一版成品。

### 2.3 重试不再覆盖用户原话

`pipeline.py` 第二轮把用户原话作为**硬约束追加**，而不是用评委 issues 替换；同时把上一版成品给生成模型，避免「为了讨好评委把用户禁用的方法请回来」。

### 2.4 同方法硬闸

用户明确说「换个方法」（intent=change_method）而评委判定新稿与旧稿同方法时，直接判不通过，防止「换措辞不换招」蒙混。

### 2.5 两轮不过 → unverified 交付

旧行为：两轮不过抛 `PipelineError`，整词白卷。新行为：交付历史最高分那版，`unverified=true`、`reason` 写明原因，App 在学习页卡片上显示「未复核 原因」。用户至少有一版可用，且知道它没复核。

### 2.6 收尾补丁（验收 B1 之后）

- `normalize()` 原先要求**末行**必须含 `——>`；用户说「最后顺带提一嘴」时模型常把旁注放在结论后面，整轮 90 秒生成白跑、p95 被推高。现在「末行无箭头、但倒数第二行有箭头」也接受，合法旁注不再判废。
- 润色后按最终稿复扫用户禁令（`_text_hits(allow_last_note=True)` 对单行文本不再跳空）；命中禁令的稿子不许当「已复核」交付——要么重试，要么落到 `unverified=true` 并写明原因。
- 新增两条单测：末行旁注可归一、单行禁令检查不失效（`tests/test_feedback.py`，共 19 条）。

## 3. 未复核的展示（A1）

- 数据链路：`RewriteResultDto.unverified/reason` → `tb_word_memory` 与 `tb_book_memory` 加列（DB 20→21）→ DAO 投影 `ApproachReview` → `observeApproachReview`（先按书、没有再回退到词级）→ `LearningViewModel` → 卡片上的 `UnverifiedChip`。
- 用户对这张卡做任意一次正常操作（如「认识」提交后 undo 清标记）后，标记消失。
- 词库/旧数据默认 `unverified=false`、`reason=""`，不影响既有卡。

## 4. 后台同步（A1）

- 用平台 `JobScheduler`（`BackgroundSyncJobService`），不引第三方依赖（WorkManager 会加包体和初始化成本）。
- 约束：15 分钟周期 ±5 分钟、`NETWORK_TYPE_ANY`、`setPersisted(true)`、只在已配置地址时注册；执行时复用 `syncOnce()` + mutex + 5 分钟节流，`onStopJob` 返回 true 以便重排。
- 前台 `onResume` 同步保留。后台任务只做同步，不做重写生成。

## 5. 服务端加固（S1）

- `_guard` 顺序改为 **401 → 403 → 429**：未鉴权请求不再消耗限流额度，也不会被 429 掩盖成「限流」。
- `/sync/*` 独立限流桶：120/min、20000/day per peer，与写桶（`/rewrite/*`、publish、rollback）互不挤占；`/health` 不受限。
- `sync_store`：
  - 原子写（临时文件 + `os.replace`）；
  - 坏文件备份为 `.corrupt-YYYYmmdd-HHMMSS`（同秒 -2 不覆盖），按原文最大 rev 重建而不是重置 0；
  - 冲突不再静默丢，返回 `conflicts` 列表并记日志；
  - `MAX_ROWS=20000`，按 rev 清最旧并返回 `trimmed`。
- `_key()` 恢复真 NUL 分隔（1.4.7.1 开发中曾被改成字面量 `\u0000`，会让旧数据全部查不到；已加契约测试锁死）。
