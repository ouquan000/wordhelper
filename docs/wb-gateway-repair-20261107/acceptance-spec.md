# WB 网关修复验收规格（2026-11-07）

状态：冻结。执行方不得改本文或锁文件。测试、独立复核均在开始和结束校验 SHA-256。

## 授权与边界

用户已授权迁移占用 8790 的英语 App 联调假服务、恢复 WB 主网关、补守护与主池健康检测，并交付故障报告。只改相关脚本；不改账号、凭证、模型、额度、QQ 在线/离线迟滞与 5:3 权重，不升级 Go 二进制，不动真实手机的学习数据，不发送真实模型请求。线上只做 GET 验证；隔离测试可对假服务器 POST。

受控进程只有：经命令行和创建时间再次核对的旧 stub、修复过程中自己启动的测试进程、部署时经身份核对的入口路由。不得杀端口上身份未知的进程。真实主池与辅池不为测试而停机。入口部署前先确认池中无在途请求，部署后立即核验。

## 固定验收项（总分100）

1. G1 迁移（15分）：8790 监听属于 run/wb2api.exe，GET /healthz 返回 workbuddy2api 服务身份；stub 默认使用确认空闲的非网关端口，可显式指定端口且拒绝 8788/8789/8790；不为验证写入真实 App 队列。
2. G2 主链路恢复（15分）：8790 与 8788 的 /healthz、带鉴权 /v1/models 均返回正确服务/模型目录，入口面板可用；8789 仍保持原进程，不改账号配置。
3. G3 启动身份检查（15分）：主启动器发现 8790 已监听时核对可执行文件路径与健康服务身份。正确进程健康则幂等跳过；外来进程占用时明确报冲突并非零退出，不强杀它；正确 WB 进程暂时不健康时报告异常且不重复启动、不误杀。
4. G4 守护（15分）：覆盖入口8788、主8790、辅8789；区分身份正确且健康、正确进程暂不健康、端口缺失、外来占用；外来占用必须显式报告，不能声称正常，不能杀进程；保留配置消毒与 .hold-restart 约定；健康失败不触发无条件杀重启。
5. G5 主辅健康路由（25分）：两池均验证 /healthz 的 JSON 服务身份和有效 healthy 数，拒绝任意200/404假服务。离线且辅池未暂停时，仅向健康池发送新推理请求；两池健康仍5:3。QQ在线或辅池暂停时不借用辅池，主池不健康返回明确503。两池都坏返回503。面板/状态/模型目录仍只指向主池，主池不健康明确失败而不混入辅池数据。身份与健康可在 /_router/status 观察。
6. G6 不重放与流式（15分）：请求发出后的404/429/连接中断不自动跨池重放；流式SSE不缓冲、不断句、客户端取消可终止转发。用隔离假服务器验证，没有真实模型调用。所有测试进程结束并清理自建临时数据，保留正式规格/测试/报告与必要证据。
