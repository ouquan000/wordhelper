# 墨墨背单词 · 卡片格式与内容组织调研报告

> 调研日期：2026-11-06
> 方法：官方文档 + 官方开放 API 文档 + 官方答疑页
> 可信度标注：**官方文档**（原文可查）/ **推断**（有依据但未明说）/ **未证实**

---

## 结论先行

墨墨背单词里**没有「卡片」这个概念**——它的单位是「一个单词的复习页」。这个页面由**三块内容**拼成：

> **释义 · 助记 · 例句**

每一块都可以**单独展开、单独筛选来源**；系统默认取「所选标签下的官方内容，或赞值最高的内容」。真正的「卡片格式」（正面/背面、答案线、挖空）属于另一款产品**墨墨记忆卡**，不是背单词。

这个设计的关键不在版式，而在于：**内容被拆成可替换的多条记录，而不是一个字段**。

---

## 一、复习页的真实结构

官方原文（《筛选 释义 / 助记 / 例句 内容标签》，**官方文档**）：

> 复习页面里，每个单词下方都会显示释义、助记、例句。你也可以点击释义 / 助记 / 例句区域右侧三横杠更多内容入口，进入详情页查看更多内容。
>
> 点击列表右上角筛选按钮，选择所需标签。筛选后，单词默认内容更换为所选标签下的**官方内容或赞值最高的内容**，无需手动修改。

拆出来是三层：

| 层 | 内容 | 交互 |
| --- | --- | --- |
| 单词本体 | 拼写、音标、发音 | 常驻 |
| 三块内容 | 释义 / 助记 / 例句 | 各显示一条「当前选中」，右侧「≡」进详情列表 |
| 详情页 | 该词在某块下的**所有条目** | 可筛选标签（绿=选中，灰=未选），选完自动换默认展示 |

**「赞值最高的内容」这句很关键**——说明同一块内容有多条来源，官方之外还有社区贡献，用投票排序。这解释了墨墨为什么能覆盖几十万词：内容不是一个人写的。

## 二、三块内容各自的存储形态（开放 API 反证）

墨墨开放 API 把这三块分别做成了三种资源（**官方文档**，`memo-api/references/`）：

### 2.1 释义 `interpretations` — 多条 + 标签

| 字段 | 说明 |
| --- | --- |
| `interpretation` | 释义文本，如 `n. 苹果; 苹果公司` |
| `tags` | 最多 3 个：`简明` `详细` `英英` `小学` `初中` `高中` `四级` **`六级`** `专升本` `专四` `专八` `考研` `考博` `雅思` `托福` `托业` `新概念` `GRE` `GMAT` `BEC` `MBA` `SAT` `ACT` `法学` `医学` |
| `status` | `PUBLISHED` / `UNPUBLISHED` / `DELETED` |
| `created_time` / `updated_time` | 创建 / 更新时间 |

**一个词可以有多条释义**，用标签区分「简明 vs 详细」「六级 vs 考研」。这是他们对「一词多义 / 多考试口径」的解法：**不拆字段，拆记录 + 打标签**。

### 2.2 助记 `notes` — 21 种类型 + 自由文本

| 字段 | 说明 |
| --- | --- |
| `note_type` | `联想` `谐音` `派生` `词根` `词源` `固搭` `语法` `对比` `近义` `反义` `扩展` `串记` `口诀` `合成` `吐槽` `其他` `固定搭配` `词根词缀` `辨析` `近反义词` `图例` |
| `note` | 自由文本，如 `apple 谐音"阿婆" → 阿婆在吃苹果` |
| `status` | `PUBLISHED` / `DELETED` |

**助记不是结构化字段，是「类型标签 + 一段文字」**。类型是可枚举的（21 种），内容是自由的。一个词可以挂多条不同类型/不同来源的助记。

> 注意 `图例` 这一类型：说明助记可以带图（至少产品概念上留了这个位）。具体渲染方式**未证实**。

### 2.3 例句 `phrases` — 句子 + 译文 + 标注区间

| 字段 | 说明 |
| --- | --- |
| `phrase` | 例句原文 |
| `interpretation` | 中文翻译 |
| `tags` | 最多 3 个，含 `词典` `短语` 及各类考试标签 |
| `highlight` | **单词在句中的字符区间数组**，半开区间 `[start, end)` |
| `origin` | 来源，如 `自编` / `词典` |

`highlight` 这个字段值得单独说：它不是靠前端正则找单词，而是**制卡时就把「哪个词该高亮」算好存起来**。这样同一个句子里出现变形（abandoned / abandoning）也能精确标中。

## 三、内容从哪来

| 来源 | 证据 | 可信度 |
| --- | --- | --- |
| 官方编辑 | FAQ 原文「官方内容或赞值最高的内容」 | 官方文档 |
| 社区共享 + 赞值排序 | 同上；助记/释义/例句都能由用户创建 | 官方文档 |
| 用户自建（只对自己可见） | 开放 API 全部资源都 scoped to the authenticated user | 官方文档 |
| 云词本（自选词表） | `notepads` 资源、云词本功能页 | 官方文档 |

顺带一个反直觉结论：**墨墨的「卡片格式」其实是社区内容生态的产物**——先有大量可替换的内容条目，再有「挑哪条显示」的规则。没有那批内容，格式本身没有意义。

## 四、真正的「卡片」在墨墨记忆卡（另一款产品）

墨墨记忆卡（Markji）才是正面/背面的卡片模型。官方答疑页（《答案线限制说明 及 单卡片多知识点制卡方法》，**官方文档**）暴露了它的结构：

- **答案线（answer line）**：一张卡最多 9 条，是正面/背面的分界与挖空标记；
- **文字挖空 / 图片遮罩**：网页端支持的两种遮挡方式；
- 支持导入 `PDF / Excel / Word / PPT / 图片` 制卡，支持导入 **Anki `.apkg`**，支持图片批量导入；
- 填空题卡片有独立的「答案及反馈交互逻辑」。

**这条对我们很重要**：如果目标是「一张卡上有多个知识点」，墨墨的答案是「挖空/遮罩 + 答案线」，而不是「把一个字段堆得越来越长」。

## 五、学习交互（题型）

背单词侧的作答只有四档（**官方文档**，`StudyResponse`）：

| 值 | 中文 |
| --- | --- |
| `FAMILIAR` | 认识 |
| `VAGUE` | 模糊 |
| `FORGET` | 忘记 |
| `WELL_FAMILIAR` | 熟知 |
| `CANCEL_WELL_FAMILIAR` | 取消熟知 |

没有 Anki 的 Again/Hard/Good/Easy 四档评分。官方有专页解释「认识/模糊/忘记/熟知该怎么选、对下次出现有什么影响」，说明**这四档直接决定排程**，而不是「打分」。

记忆卡侧另有「新学：认识 / 忘记」两档起点。

## 六、对我们这个项目的直接启示

### 可以立刻借鉴的 4 点

1. **释义按「词性 / 义项」拆行，不按句子硬切**。我们现在用 `；` + 词性正则分行（`v. …` / `n. …`），方向对；墨墨更进一步是「多条记录 + 标签」，我们至少应保证**每条义项独立成行**。
2. **助记用「类型 + 文本」而不是裸文本**。我们现在 `approach` 是一个字符串存 ①②③；如果以后要支持多种思路（词根/谐音/联想/串记），加一列 `approachType` 比改结构便宜。
3. **例句带高亮区间**。我们现在的例句是整句显示，单词没标出来。加一个 `highlight` 区间（制卡时算好）能明显提升可读性，成本很小。
4. **内容来源要留位**。哪怕只有你自己写的内容，也建议在表里留 `source`（`self` / `ai` / `import`），将来「哪条是 AI 生成的、哪条是我改过的」才分得清。

### 不必照抄的 2 点

1. **赞值排序 / 社区内容池**：我们是单人使用，没有投票，也不需要。
2. **答案线 / 挖空**：那是记忆卡的模型，我们的卡背是「释义 + 思路 + 搭配」的阅读型版式，不需要挖空交互。

## 九、交叉复核补充（子智能体独立取证）

1. **没有「翻面」这个动作**。复习页是单页纵向堆叠：单词 → 释义 → 助记 → 例句 → 底部四键（认识 / 模糊 / 忘记 / 熟知）；每个区块右侧有「三横杠」进详情页看候选内容。官方文档没有描述任何翻面或遮罩动作。
2. 四键语义（**官方文档**）：认识 = 当天不再出现、间隔逐步拉长（最长一年）；模糊 = 当天至少再出现 1 次；忘记 = 当天必定再出现 1 次且大概率次日再来；熟知 = 永久不再复习。
3. **只有当天第一次反馈影响长期调度**，当天后续反馈只改当天内间隔；「今日回顾 / 历史回顾」里的反馈不影响长期调度。
4. 题型只有两个开关：看中文回忆英文（含拼写验证）、验证拼写。没有选择题 / 听力题 / 例句填空——填空卡属于墨墨记忆卡。
5. **导入只有「云词本」**：纯文本一行一词、`#` 开头为章节名、首行 `//` 可提取原型（saw→see）；云词本只装词表，不含每词的释义 / 助记 / 例句。没有 CSV / Anki `.apkg` / Excel 导入。
6. **导出只有 PDF**（LVL 3，单次 ≤12000 词），模块可勾选；图片助记与「超级释义」导不出，无结构化导出。
7. 内容来源是三层混合：官方编辑 + 用户共享（**同池竞争，按赞值决定默认展示哪条**）+ 算法只做挑选不做撰写。
8. 一处官方口径矛盾：「开放 API 功能介绍」页宣称第三方可调取释义 / 例句 / 助记，但 API 参考文档写的是用户私有范围（`/vocabulary` 只返回 id + spelling）→ 以参考文档为准。
9. 未证实项：① 是否允许隐藏释义（「先自己想再点开」的设置）；② 图片助记的官方形态与存储方式（schema 无图片字段，但导出文档承认「图片助记无法导出」）。
