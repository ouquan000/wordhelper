## 1. 正/背面判定方法（唯一口径）

不许靠肉眼看截图猜。一律用可访问性树：

```bash
adb -s emulator-5554 shell uiautomator dump /sdcard/ui.xml
adb -s emulator-5554 exec-out cat /sdcard/ui.xml
```

判定顺序（先判正面，避免「释义」二字在正面提示语里误命中）：

1. 出现 `轻触卡片查看释义与例句` → **正面**
2. 否则出现下列任一 → **背面**：`记忆思路`、`常用搭配`、`EF系数因子`、`近义词`、`同根词`、`短语`
3. 都没有 → `UNKNOWN`，本次测量作废重来（不要猜）

> 为什么是这组标志：卡背滚到底后「释义」「记忆思路」标题会滚出屏幕，只剩「常用搭配」等区块，只认一个标志会误判成 UNKNOWN。

每次操作后等 **1200ms** 再 dump（翻面动画 300ms + 模拟器慢，等短了会读到动画中间态）。

## 2. 功能项（F1–F8，每项 10 分，共 80 分）

> **F1–F8 全部拿到 10 分，才算「功能合格」。任何一项 0 分 → 总判定不合格。**

卡片点击坐标固定用 `(540, 1056)`（卡片 `[44,378][1036,1735]` 的几何中心）。
滑动坐标：起 `(540,1450)` → 止 `(540,780)`（向上滑 670px）；反向为 `(540,900)` → `(540,1570)`。

| ID | 测试内容 | 操作 | 通过标准 |
|---|---|---|---|
| **F1** | 正面轻点翻到背面 | 正面下 `input tap 540 1056` | 等 1200ms 后 dump = 背面 |
| **F2** | 背面轻点翻回正面 | 背面下 tap 同点 | 等 1200ms 后 dump = 正面 |
| **F3** | 卡背上下滑动**不**翻面 | 背面下，向上滑 5 次、向下滑 5 次（每次间隔 600ms） | 10 次滑完仍为背面。中途任何一次变正面即 0 分 |
| **F4** | 卡背滑动后**立刻**点击仍能翻回正面 | 背面 → 快速上滑（时长 120ms）→ **间隔 ≤250ms** 立刻 tap → 等 1200ms | 5 轮全部回到正面。任一轮失败即 0 分 |
| **F5** | 按压全程**无水波纹** | 见 §3 判据 | 卡片区域 按住态 vs 静止态 平均色差 **< 2.5/255** 且 差值>6 的像素占比 **< 1%** |
| **F6** | 点卡内控件不连带翻面 | 背面下点右上角星星 `(915,499)` | 仍为背面（1500ms 后 dump） |
| **F7** | 正面左右滑功能未被改坏 | 正面下从 `(700,1056)` 滑到 `(200,1056)`，时长 250ms | 词条或进度发生变化（`increase` → 别的词 / `1/11` → 变号），且**不是**翻面 |
| **F8** | 卡背滚到底部再点击仍能翻回正面 | 背面下连续上滑 3 次到底 → 等 800ms → tap 中心 | 等 1200ms 后为正面 |

**F4 实施细则**：`input swipe` 与 `input tap` 之间必须由**同一条 shell 命令连续下发**，中间不允许插入 dump / 截图 / sleep（脚本进程开销会让间隔超标，测不出真实场景）。

## 3. F5 水波纹判据（唯一取证方式）

用「原地按住」取样，避开翻面动画干扰：

```bash
# 1) 静止态
adb exec-out screencap -p > rest.png
# 2) 原地按住 1500ms，在第 600ms 截图
adb shell input swipe 540 1056 540 1056 1500 &
SW=$!
sleep 0.6
adb exec-out screencap -p > press.png
wait $SW
# 3) 松手后归位（此步会翻面，属正常，需再 tap 一次回到原状态）
```

计算时**只取卡片矩形** `x∈[44,1036], y∈[378,1735]`：

```python
diff = np.abs(rest.astype(int) - press.astype(int)).mean(axis=2)
mean_diff = diff.mean()
pct_gt6   = (diff > 6).mean() * 100
```

- `mean_diff < 2.5` **且** `pct_gt6 < 1.0%` → 通过（10 分）
- 否则 → 0 分（附两张截图 + 两个数字）

> 基线参考：修复前该值 = **19.71 / 98.13%**。

## 4. 体验项（E1–E2，每项 10 分，共 20 分）

| ID | 测试内容 | 方法 | 判定 |
|---|---|---|---|
| **E1** | 翻面动画连贯，无黑屏/白闪/中间空白 | `screenrecord --time-limit 6 --size 540x1170` 录制一次 F1+F2，ffmpeg 抽帧到 30fps，逐帧看 0→90°→180° 过渡 | 无纯黑/纯白帧；正反面之间无「半张空白」帧；旋转方向一致。全满足 10 分，出现任一异常 0 分 |
| **E2** | 快速连点不卡死、不错位 | 正面下连续 tap 6 次，间隔 300ms；再等 2s | App 不 ANR、不闪退；最终停在正面或背面（任一均可）；之后单次 tap 仍能正常翻面 |

**帧率单列，不评分**：`dumpsys gfxinfo` 在 headless + swiftshader 下 100% janky、50 分位 150ms，不可用于判定。执行方需采集一次原始数据附在报告末尾，明确标注「环境不可用，仅记录」，**不得**据此加减分。

## 5. 评分与结论

- 功能分 = F1..F8 各 10 分之和（满分 80）
- 体验分 = E1 + E2（满分 20）
- **总判定**：F1..F8 全为 10 分 → 「功能合格」；否则「不合格」
- **总分** = 功能分 + 体验分（满分 100）
- 报告里两个结论都要给：`功能合格/不合格` + `总分`
